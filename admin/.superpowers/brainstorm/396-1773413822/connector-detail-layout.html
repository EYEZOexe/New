Connector detail page — how should it be organized?

Currently everything is on one long scrolling page. Here are 3 approaches.

A

Tabbed layout

Break the page into tabs: Overview (status + runtime info), Routes (source→target mappings), Jobs (recent mirror jobs), Settings (token, seat configs). Each tab is focused and fast to reach directly from the URL or sidebar.

B

Two-panel layout

Left panel: connector status + controls + runtime info (sticky). Right panel: scrollable content with collapsible sections for Routes, Jobs, Seat configs. No tabs — everything visible at once but organised with clear headings.

C

Restructured single page

Keep single-page but fix organisation: sticky status bar at top, then summary cards (jobs, latency), then full sections below in logical order. Jobs surface near the top instead of buried at the bottom. No tabs needed.
