Connector detail page — how should it be organized?

Currently everything is on one long scrolling page. Here are 3 approaches.

A

Tabbed layout

Break the page into tabs: Overview (status + runtime info), Routes (source→target mappings), Jobs (recent mirror jobs), Settings (token, seat configs). Each tab is focused and fast to reach directly from the URL or sidebar.

B

Two-panel layout

Left panel: connector status + controls + runtime info (sticky). Right panel: scrollable content with collapsible sections for Routes, Jobs, Seat configs. No tabs — everything visible at once but organised with clear headings and collapsibles.

C

Keep single page, restructure it

Keep the single-page approach but fix the layout: sticky header with status + controls, then clearly separated card sections below. Jobs section moves to the top (just below the header) rather than buried at the bottom. Simpler than tabs but much better than the current scroll-to-find-it layout.
